## 1. Назначение проекта

ARMORA — производитель премиальных стальных входных дверей (Клин, Россия). Текущий проект — **витрина-каталог** в виде статических HTML-страниц без бэкенда. Конечный пользователь:
- листает каталог дверей,
- открывает калькулятор-конфигуратор для выбранной модели,
- получает расчёт цены и оставляет заявку на бесплатный замер.

Сайт визитки/основного бренда живёт отдельно на `https://armora.ru`. Этот проект — расширенный «каталог», на который ведёт кнопка «Перейти на сайт».

## 3. Главные файлы

### 3.1 `catalog.html` — публичная витрина (~174 КБ, ~2970 строк)

**Single-file HTML**: всё inline — стили, JS, данные. Внешние ассеты только: Google Fonts (Cormorant + Manrope + Montserrat), `bg.png`, `img/doorXX.*`.

#### Архитектура внутри файла
| Диапазон строк | Что там |
|---|---|
| `1–28` | `<head>`: meta, SEO, OG, JSON-LD, preload `bg.png`, Google Fonts |
| `30–50` | `<noscript>` fallback + JSON-LD `CollectionPage` |
| `~52–1730` | inline `<style>` (~120 КБ) — 3 «волны темы»: lime-accent, силвер, liquid-glass |
| `1731–1879` | разметка `<body>`: hero, toolbar, фильтры, grid, drawers, чат |
| `~1920–2970` | inline `<script>`: данные, рендер, фильтры, калькулятор, лиды, корзина/сравнение |

#### Ключевые JS-структуры (catalog.html)
- `DOORS[]` — массив моделей, **захардкожен** в `:1988-2010` (≈30 дверей).
- `FINISHES{}` (`:1921`) — справочник внешних отделок: ключ → label + цвета фолбэк-SVG.
- `GLASS_OPTS[]` (`:2088`) — варианты вставок/стеклопакетов.
- `CALC_STEPS[]` (`:2411+`) — шаги конфигуратора: серия → отделка снаружи/внутри → стеклопакет → уплотнение → замок → ручка → доп.опции → размеры → лид.
- `WISH`/`CMP` (Set) — избранное / сравнение в `localStorage` (`armora_wish`, `armora_cmp`).
- `FILTERS{}` (`:2050+`) — состояние фильтров (purpose, series, finish, glass, search, priceMax).
- `LS{get,set}` — обёртка над `localStorage` с try/catch.

#### Ключевые функции
- `cardHtml(d, idx)` (`:2202`) — рендер карточки.
- `slideHtml(src, alt)` (`:2044`) — рендер слайда; принимает SVG-строку или URL.
- `render()` (`:2296`) — пересортировка/перерисовка `#grid`.
- `renderChips()` (`:2106`) — фильтр-чипы.
- `openCalc(id)` / `closeCalc()` (`:2312, :2326`) — модалка калькулятора.
- `renderCalc()` (`:2533`) — рендер текущего шага; обёрнут monkey-patch для добавления кнопок «Смета»/«Ссылка» (защищён флагом `__armoraWrapped`).
- `submitLead()` — приём заявки, валидация телефона, success-экран.
- `attachPhoneMask()` — маска телефона (защищён `dataset.maskBound` от двойной привязки).
- `saveCalcToURL()` — debounced (300 ms) сохранение конфигурации в `?door=&base=&...`.
- `restoreFromURL()` — поднимает состояние из querystring.
- `downloadEstimate()` — генерация текстовой сметы.

#### Темы и визуал
- CSS-переменные в `:root` (`:11-50`): `--font-display`, `--font-sans`, `--accent`, `--ink`, `--bdr` и т.п.
- Liquid-glass — финальная тема (последний каскад `:1153+` с `!important`-ами).
- Карточки на тёмном `#15161a`, без backdrop-filter (фикс «дрожания» при перелистывании слайдов, 27.04).

### 3.2 `doors-editor.html` — админка (~20 КБ, ~464 строки)

Локальная утилита для контент-менеджера, **полностью клиент-сайд**. Хранит данные в `localStorage` ключом `armora_doors_v1`.

#### Возможности
- Таблица всех моделей с inline-редактированием (`<input>`/`<select>` в каждой ячейке).
- Поля: name, purpose, metal, ext/int отделка, glass, seal, lock, handle, extras (мульти-чекбокс), oversize/double, finish_color, flag, popular, photos.
- **Авторасчёт цены и серии** функцией `compute(row)` (`:217`) на основе прайса `PRICES{}` и `METAL_BASE{}`. Серия выбирается по порогам цены: ≥20k=Стандарт, ≥30k=Комфорт, ≥45k=Премиум, ≥65k=Элит.
- Подсветка ошибок валидации в правой колонке.
- Кнопка «+ 10 городов» — пакетная вставка из пресета `CITY_PRESETS` (≈140 названий городов).
- Экспорт: CSV, JSON (включая `_price`/`_series`), копирование JSON в буфер.
- Очистка всего каталога с подтверждением.

#### Прайс-лист (зашит в editor :125-181)
- **Металл (база)**: 1.2 → 12 900 ₽, 1.5 → 19 900 ₽, 1.8 → 24 900 ₽, 2.0 → 29 900 ₽.
- **Внешняя отделка**: Винилискожа 2 500 → 3D-панель 27 000.
- **Внутренняя**: Винилискожа 2 500 → Фанера 17 000.
- **Стеклопакет**: Без вставки 0 → Художественный витраж 25 000.
- **Уплотнение**: 1/2/3 контура 0 / 2 500 / 12 000.
- **Замок**: стандарт 0 → Биометрический 25 000.
- **Ручка**: MSM 0 → Бугельная 16 500.
- **Extras**: Видеоглазок 6 500, Доводчик 5 500, Терморазрыв 10 500, Скрытые петли 23 000 и т.д.
- **Множители**: oversize × 1.20, двустворчатая × 1.40.

#### Workflow редактора (текущий)
1. Открываешь `doors-editor.html` в браузере.
2. Правишь в таблице → автосейв в `localStorage`.
3. Жмёшь «Скачать JSON» → получаешь `doors.json`.
4. **Вручную** копируешь содержимое в `catalog.html`, заменяя массив `DOORS[]` (на сегодня связь не автоматизирована).

⚠ **Disconnect**: `doors-editor.html` и `catalog.html` живут параллельно. Editor умеет экспортировать, но catalog не умеет импортировать — данные синхронизируются вручную. Это известный технический долг (см. раздел 6).

### 3.3 `img/door01..10.*` — фотографии моделей

Имя файла = `id` двери в `DOORS[]`. Сейчас в `DOORS` ссылок на эти файлы нет (используется `images:[svgRender(...)]` или захардкоженные пути) — точная связка хранится внутри массива моделей (см. `:1988+`).

## 4. Технологический стек

- **HTML/CSS/JS без сборщика**, без фреймворков, без бандла.
- **Шрифты**: Google Fonts → Cormorant (display, заголовки), Manrope (UI/основной), Montserrat (legacy).
- **Хранение состояния**: `localStorage` (избранное, сравнение, черновик каталога в editor).
- **Хранение данных каталога**: захардкоженный JS-массив `DOORS` в `catalog.html`.
- **SEO**: meta description, canonical, Open Graph, JSON-LD `CollectionPage`.
- **A11y**: `aria-label` у инпутов и кнопок, `tabindex+role=button` у карточек, `<noscript>` fallback.
- **Хостинг**: предполагается статический (`armora.ru/catalog`), CDN/preload `bg.png`.

Никаких npm/Node-зависимостей в самом проекте нет. Node нужен только для синтакс-чек скриптов разработчиком.

## 6. Известные архитектурные проблемы

### 6.1 Editor ↔ Catalog не связаны
`doors-editor.html` экспортирует JSON, но `catalog.html` его не читает — данные руками копипастятся в `DOORS[]`. Решение: либо `fetch('doors.json')` в каталоге, либо локальный Node-сервер.

### 6.2 Фото моделей подключаются ссылками
В `DOORS` поле `images` — массив URL/SVG. Нет договорённой структуры папок «папка на дверь». Обсуждалось 27.04, решение отложено.

### 6.3 Single-file монолит
166 КБ в одном файле = полный re-download на каждом hit. Без CDN gzip ≈45 КБ — терпимо, но split на `style.css`/`app.js` дал бы кеширование.

### 6.4 Дубли тем в CSS
`:root` определяется трижды (`:11`, `:1153`, ещё одна тема). Каждая новая итерация переписывала старую через `!important`. Чистка отложена.

## 7. Рекомендации на следующий этап

В порядке приоритета:

1. **Связать editor и catalog**: `doors.json` отдельным файлом, `catalog.html` грузит через `fetch`. Закроет п.6.1 + п.6.2 одновременно (вместе с папками `img/doors/<id>/`).
2. **Положить favicon.ico** и **`img/og-catalog.jpg`** в проект.
3. **Заменить тестовые контакты** на реальные.
4. Вынести inline CSS/JS в `style.css`/`app.js` для долгого cache-control.
5. Чистка `!important`-каскада и мёртвых классов (см. отчёт code-review).
